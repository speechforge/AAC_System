## 7. Evaluation protocol (frozen before scoring)
- **Scenarios** (`eval/build_scenarios.py` -> `fixtures/scenarios.jsonl`, SHA-256 `61607e1b...`): 4 languages x 46 (10 food requests, 10 refusals `No`+food, 8 feelings, 8 negated feelings, 6 action+object, 4 help/call+person) = 184, plus 8 Hinglish exploratory (`code_mix=true`, `hi`). Concept IDs come from the board (`fixtures/board_vocab.json`, 69 symbols, extracted from `index.html`).
- **Change log before scoring:** the structured intent for feelings was first `FEELING`; `llm.py` showed the hi/gu/mr builders only recognise REQUEST/WANT/STATEMENT/FEEL, so it became `STATEMENT`. The aborted first run (54 requests) is `logs/aborted_run1_feeling_intent_raw.jsonl`. Pilot traces (14 requests) had been seen before the freeze.
- **Payloads:** `client` = built with the web client's substring rules; `structured` = explicit `intent`/`negation`, "No" removed from entities. 294 unique requests sent to `POST /generate` (live server, `generation_mode=dual`); timeouts/errors: **0**.
- **Systems:** literal join; backend template alone (`generate_deterministic_fallback`, no model load); naive Qwen (`eval/run_naive.py`: system prompt "You are an assistive communication tool..." + "Selected symbols: ...", greedy, `max_new_tokens=75`, same `IndicLLM._call_llm`); cascade before gate (`llm3_decision.final_text` of the same response); deployed (`text`). `llm1`/`llm2` stage rows are also scored.
- **Scorer** (`eval/score.py`, lexicon `fixtures/lexicon.json`, SHA-256 `c69c1af6...`; shares no code with `semantic.py`): `success` = every required concept present (concept instances) and polarity correct (negator present iff gold negated) and gold act expressed (request marker; or feeling marker without request marker) and no added concept (any other board concept or time/meal/venue word, overlap-aware) and not off-task (refusal/meta text, third person "the user", empty, >25 tokens, Latin text in an Indic target) and target script. Lexical only; **lexicon not native-reviewed**; written by the authoring assistant.
- **Denominators:** concept retention over concept instances (215 in the primary set); polarity/act/added/off-task over scenarios (175). Per-language N: EN 46, HI 45, GU 42, MR 42.
- **Exclusions:** 9 scenarios whose few-shot query string reproduces an in-prompt example for either payload (parsed from `llm.py` by `analyze.py`): `hi-T1-WATER`, `gu-T1-WATER`, `gu-T1-FOOD`, `gu-T2-NO+FOOD`, `gu-T3-HAPPY`, `mr-T1-WATER`, `mr-T1-FOOD`, `mr-T2-NO+FOOD`, `mr-T3-HAPPY`. Sensitivity on all items is in `summary.json` (`all_items`).
- **Pairing/uncertainty:** paired by scenario; bootstrap over scenarios, 10,000 resamples, seed 20261111 (`config.json`); exact (Clopper-Pearson) bounds for 0/175 and 215/215; prediction: cluster bootstrap over source conversations (60 per language).
- **Stochasticity:** LLM-1 samples at temperature 0.1 for English and code-mixed output (no server seed): single sample per payload, not repeated. Indic path greedy. Repetition runs are not done; run-to-run variance is unmeasured.
- **Prediction split:** `eval/predict_eval.py`: source index k = 100*batch + row; held-out if k % 5 == 0 (60 sources/language); `transformed` and `augmented` rows aligned by turn/speaker signature (all 300 rows verified, also for Hindi); training = remaining sources (both files) + seed corpus; test = AAC-user `utterance_intended` of held-out sources (transformed file only), contexts j>=1; OOV targets count as misses (7.5% EN, 5.5% HI); 392/384 distinct test utterances, 18/28 seen verbatim in training. Baselines: unigram, stupid-backoff bi/trigram (same tokens, same exclusion of already selected words).
- **Latency:** wall time of HTTP `POST /generate` per unique request (283, code-mixed excluded), warm server; TTS in placeholder mode (t_tts about 0). Cold start: ready 10.2 s, first request 13.94 s (`offline_summary.json`).
- **Reliability probes:** invalid request -> 422; unknown voice delete -> 400; CDN-blocked page -> 0 visible characters; Un-Jumble API returns input order without HMM-2; keyboard Tab/Enter/Space select symbols; emulated touch tap selects; ARIA: 69 buttons all named, 0 `aria-label`, 0 live regions (`results/reliability_ui.json`). Offline guard: only `inputtools.google.com` DNS attempted. CUDA OOM with two servers on the 4 GB GPU -> 2 pipeline errors -> template (evidence log).

## 9. Negative and unexpected findings
Template-only beats the pipeline; gate accepts wrong-act outputs (49% precision under the client payload); client sends REQUEST for 27/32 feelings; validator intent test is English-only; template `NEGATION` branch missing ("I want No Pizza."); Indic negated feelings -> negated wants; "Nose" false negation; fallback accepted unconditionally and invisible in the UI; "Accuracy: 100%" and "IndicF5 Voice" shown for placeholder audio; no Gujarati/Marathi predictor; retry is a no-op for Indic (greedy) and doubles latency; validator misses "cannot"/"can't" as negators (rejects "I cannot eat pizza."); `Un-Jumble` silent without HMM-2; two model copies OOM on 4 GB. The proposal's baseline figures (14.2% CVR, 18.5% negation drop, 1.5 s) do **not** appear in `francis25_interspeech.pdf` (no LLM, hallucination or negation analysis there); do not reuse.
