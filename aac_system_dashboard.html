1. Communication Rate Dilemma

Telegraphic symbol selection on static speech-generating devices (SGDs) yields 2–8 Words Per Minute (WPM), compared to 130–160 WPM in fluent speech. Non-verbal users suffer extreme communicative fatigue and conversational drop-off.

Solution: O(1) Markov Bigram HMM (<1ms latency)
🇮🇳

2. Linguistic & Cultural Homogeneity

Commercial SGDs (Tobii Dynavox, Proloquo2Go) are built almost exclusively for Standard English. They neglect Indic Subject-Object-Verb (SOV) order, dative experiencers (मुझे भूख लगी है), honorific agreements, and conversational Hinglish code-mixing.

Solution: Devanagari/Gujarati script few-shot realizer
🛡️

3. Generative Hallucination Hazard

Autoregressive LLMs invent fictitious times ("tomorrow at restaurant"), add unselected actions ("eating pizza"), or catastrophically invert negations ("DON'T WANT" $\rightarrow$ "I want"), which presents severe clinical patient safety hazards.

Solution: Concept Ledger + Hard Validator + Deterministic Fallback

⚠️ Codebase Vulnerability & Diagnostic Audit 8 Issues Discovered

Deep static analysis and empirical execution revealed critical path dependencies, model bypasses, signature mismatches, and offline privacy leaks.

CRITICAL

Bug 1: Hardcoded Obsolete Drive Paths (/media/linux/ShreejiPers1/...)

backend/tts.py, train_hindi_hmm_dataset.py, etc.

Multiple files contain hardcoded absolute paths pointing to an external hard drive path (/media/linux/ShreejiPers1/...) that does not exist in this environment. In tts.py, line 209 points directly to this missing path, causing FileNotFoundError if the prompt cache misses.

# indic-generative-aac/backend/tts.py: Line 209
wav_path = "/media/linux/ShreejiPers1/Future_Conference_Works/aac_system_demo_track/IndicF5/prompts/PAN_F_HAPPY_00001.wav"
Remediation: Replace with relative resolution: os.path.abspath(os.path.join(base_dir, "../../IndicF5/prompts/PAN_F_HAPPY_00001.wav")).
CRITICAL

Bug 2: Relative Frontend Mount Crash in app.py

backend/app.py: Lines 277–278

app.mount("/static", StaticFiles(directory="../frontend")) crashes on server startup with RuntimeError: Directory '../frontend' does not exist whenever the process is launched from the workspace root instead of indic-generative-aac/backend/.

# indic-generative-aac/backend/app.py
app.mount("/static", StaticFiles(directory="../frontend"), name="static") # Crashes if cwd != backend
Remediation: Anchor using os.path.join(os.path.dirname(os.path.abspath(__file__)), "../frontend").
CRITICAL

Bug 3: 1.1GB Dual HMM Bypassed via Hardcoded Early Return

backend/hmm.py: Lines 58–61

Despite finishing the 505-chunk milestone (251.01M sentences, 4.05B tokens), hmm.py contains an early return statement. The English HMM runs on a hardcoded stub of only 59 words and 27 bigrams. Furthermore, /api/unjumble is completely missing from the frontend UI!

# indic-generative-aac/backend/hmm.py: Line 58
print("[HMM Engine] Using lightweight built-in English AAC vocab (training is running in parallel).")
self._load_builtin_english_vocab()
return # <--- Hardcoded early exit bypassing hmm_model.pkl (855MB) and hmm1/hmm2!
Remediation: Remove early return; load top 30K compacted bigrams; connect UI "Un-Jumble" button to /api/unjumble.
HIGH

Bug 4: LLM-3 Latency Explosion (17.9s–33.7s) & Text Mutilation

backend/llm.py & tests/semantic/llm3_eval_report.json

In llm3_eval_report.json, LLM-3's JSON generation took 10.3s alone, producing total latencies between 14.2s and 33.7s. Moreover, deleting forbidden words created mutilated sentences like "The user felt and decided to go to the for pizza." and "I feel sad because I am and need food.", which scored 1.0 because the validator lacked syntactic coherence parsing!

# Actual benchmark outcome in llm3_eval_report.json
"candidate": "The user felt hungry and decided to go to the restaurant for pizza.",
"final_text": "The user felt and decided to go to the for pizza." # Stripped words left broken syntax
Remediation: Replace verbose JSON prompt with classification badge; add post-strip syntactic repair or deploy the fine-tuned FLAN-T5 model.
HIGH

Bug 5: Disconnect of AAC Sentence Refinement Training Kit

AAC_Sentence_Refinement_Training_Kit/

The refinement kit fine-tuned google/flan-t5-small to achieve 98.4% exact match with a blisteringly fast 31ms latency, resolving the universal *"I want"* intent bug. However, this model is completely unintegrated into indic-generative-aac/backend/app.py!

Remediation: Wire aac_refiner.py into app.py as the primary single-stage realization engine for English payloads.
HIGH

Bug 6: Crash in Evaluation & Benchmark Scripts

backend/evaluate.py & tests/semantic/evaluate_modes.py

In evaluate.py, llm.generate_sentence returns a 7-tuple, but the script assigns it to a single variable and passes 3 args to validator.validate() which expects 4 args, crashing with a TypeError. Similarly, evaluate_modes.py unpacks 3 variables from the 7-tuple, raising ValueError.

# indic-generative-aac/backend/evaluate.py
sentence = language_model.generate_sentence(...) # Returns 7-tuple!
valid, val_data = validator.validate(context, sentence, lang) # Crash: missing 1 required positional argument!
Remediation: Correct unpack signature to (gen, ctx, ledger, c1, c2, dec, telem) = ....
MEDIUM

Bug 7: TTS Script Pointing to Deprecated FastPitch Repo

download_models.sh & backend/tts.py

download_models.sh attempts to download old FastPitch checkpoints into indic-generative-aac/indictts/inference/checkpoints (a non-existent directory), while the actual active model is IndicF5-TTS stored in AI4Bharat-Indic-TTS/checkpoint/model.safetensors.

Remediation: Remove dead FastPitch scripts; consolidate TTS into a unified IndicF5 module.
MEDIUM

Bug 8: Online Dependency in Transliteration Breaks "Zero-Cloud" Guarantee

backend/app.py: Line 81

While the project documents claim 100% on-device offline zero-cloud privacy, app.py contacts https://inputtools.google.com/request for Devanagari transliteration. When offline, requests hang for 3 seconds before failing.

# indic-generative-aac/backend/app.py
url = f"https://inputtools.google.com/request?text={urllib.parse.quote(text)}&itc={itc}&num=1"
Remediation: Use an offline Python transliteration package (e.g. ai4bharat-transliteration or indic-transliteration).
