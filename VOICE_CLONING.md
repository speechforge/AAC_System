# Personal reference voices

IndicF5 supports speaker-conditioned synthesis using a reference WAV and its exact transcript: https://huggingface.co/ai4bharat/IndicF5 . It supports Hindi, Gujarati and Marathi among its published languages. The app's separate original F5-TTS model handles English.

Sign in, select the output language, then open Username → Profile settings → Personal voice. The microphone popup also has a Personal voice shortcut. Upload a clean 3–12 second WAV with one speaker (8–96 kHz mono/stereo, at most 20 MB), and enter exactly what is spoken in the selected language's native script. Use your own recording or a voice you have permission to use. Save and use my voice activates that reference for this account and language. Choose Default voice to pause its use; Delete uploaded voice removes the reference and its generated cache. For another language, select that language and supply a matching reference/transcript. Speaker similarity and pronunciation depend on the source recording and transcript and are not guaranteed perfect.

All backend word/phrase TTS and generated-sentence requests use the account selection. The model is conditioned at inference; it is not fine-tuned. CPU-only inference remains supported and can be slow on the first request. Repeated text reuses the voice-specific WAV cache. The static 80-recording demo cannot run neural cloning and explicitly labels this limitation.

Reference metadata and selection persist in the existing account Redis database. WAVs are normalized to 24 kHz PCM and kept privately at .runtime/voice_profiles/<account-hash>/. They are not served through the frontend static mount. All profile writes require the existing session CSRF token. Account ownership is derived from the authenticated session. Upload filenames are never used as paths. Unsupported, silent, non-finite and oversized recordings are rejected. Reference replacement/deletion removes matching generated cache files. Already-running inference owns an in-memory reference snapshot and does not depend on a deleted file.

The generated-audio cache key includes account, reference ID, audio/transcript fingerprint, output language, text and model settings. Custom voices cannot use the bundled default-voice sentence recordings. Clearing the general audio cache preserves uploaded reference WAVs. Private voice files, Redis user data and sessions are excluded from the portable ZIP; a destination installation creates its own accounts and uploads.

Verification: account isolation, CSRF rejection, malformed WAV rejection, native transcript validation, preference switching, deletion and cache separation unit tests; actual English F5 and Gujarati IndicF5 synthesis and sentence generation using uploaded references; repeat-cache hits; browser upload/switch/reload/delete checks at 390 and 1280 px. A reference from the existing public model prompts was used for synthesis checks. Tests establish correct pipeline routing and valid WAV output, not a human-rated speaker similarity score.
